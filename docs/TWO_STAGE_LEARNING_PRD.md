## 🎯 背景和目标

### 当前问题

1. **学习计划永不结束**
   - 只要用户没有把全部单词标记为"认识"，定时任务就会永远生成新词
   - 用户感到迷茫："到底什么时候才能学完？"

2. **进度显示不清晰**
   - 进度条只显示已标记"认识"的单词
   - 用户标记了"模糊"或"不认识"后，进度条不前进
   - 用户困惑："我明明都标记过了，为什么进度还是0%？"

3. **"完成"的定义混乱**
   - 单日任务：全部标记"认识"才算完成
   - 整体计划：也是全部标记"认识"才算完成
   - 但新词生成逻辑：`status != 'known'` 的词都会重新生成

### 产品目标

1. ✅ **学习计划自动结束**
   - 所有单词都标记过（任何状态）后，自动检测为"学习阶段完成"
   - 进入复习阶段后，不再生成新词

2. ✅ **进度显示清晰**
   - 进度条显示"已标记 / 总数"（而不是"已认识 / 总数"）
   - 用户清楚知道哪些词已经学过了

3. ✅ **两阶段清晰**
   - 学习阶段：新词 + 复习混合
   - 复习阶段：只复习已学过的词
   - 用户明确知道当前在哪个阶段

## 🧠 核心概念

### 1. 两个阶段的定义

| 阶段 | 目标 | 内容 | 完成条件 |
|------|------|------|----------|
| **学习阶段** | 学习新词，初步建立记忆 | 新词 + 复习混合 | 所有单词都至少标记过一次 |
| **复习阶段** | 巩固记忆，防止遗忘 | 只复习已学过的词 | 永久持续，根据艾宾浩斯曲线安排 |

### 2. 核心定义

#### "学过"的定义
- **旧逻辑**：标记为"认识"才算学过
- **新逻辑**：标记任何状态都算学过（"认识"、"模糊"、"不认识"都算）

#### "新词"的定义
- **旧逻辑**：`status != 'known'` 的词（模糊、不认识、未标记）
- **新逻辑**：**完全未标记过的词**（`word_progress` 表中没有记录）

#### "完成"的定义

**单日任务完成**：
- 当天任务中的所有词都标记过（任何状态）
- 不要求全部标记为"认识"

**整体学习阶段完成**：
- 词书中所有单词都至少标记过一次
- 自动检测并进入复习阶段

## 📖 用户故事

### 故事1：新用户开始学习

> 作为一名新用户，我选择了一本500词的词书，每天学习20个新词。

**第1天**：
- 系统分配：20个新词
- 我学习后，标记：
  - 10个"认识"
  - 5个"模糊"
  - 5个"不认识"
- 进度显示：20/20 已标记 (10个认识) ✓ 100%
- 今日任务完成

**第2天**：
- 系统分配：20个新词 + 10个昨天标记"认识"的词（复习）
- 我继续学习...

**第25天**：
- 系统提示：🎉 学习阶段完成！
- 说明：所有500个单词都已标记过
- 进入复习阶段

### 故事2：复习阶段体验

> 作为一名完成学习阶段的用户，我现在进入复习阶段。

**第26天（复习第1天）**：
- 首页显示：[DAY 26] [复习阶段]
- 今日任务：0个新词，25个复习词
- 任务说明：
  - 复习阶段：巩固之前学过的单词
  - 每个词只需标记一次当前状态
  - 认识的词会延长复习间隔
  - 模糊/不认识的词会重新进入学习
- 我学习后，标记：
  - 20个"认识" → 7天后复习
  - 3个"模糊" → 明天继续复习
  - 2个"不认识" → 明天继续复习
- 进度显示：25/25 已标记 (20个认识) ✓ 100%

**第27天（复习第2天）**：
- 今日任务：0个新词，5个复习词
  - 2个昨天标记"不认识"的词
  - 3个昨天标记"模糊"的词
- 继续复习...

### 故事3：诚实标记的好处

> 作为一名用户，我诚实标记每个词的真实状态。

**场景1：我标记"模糊"**
- 系统会安排我明天继续复习这个词
- 帮助我巩固记忆，不会遗忘

**场景2：我标记"不认识"**
- 系统会安排我明天继续学习这个词
- 不会直接跳过，确保我真正掌握

**场景3：我标记"认识"**
- 系统会延长复习间隔（7天 → 15天 → 30天）
- 符合艾宾浩斯遗忘曲线

**用户感受**：
- 不需要刻意追求"全部认识"
- 诚实标记，系统会智能安排
- 学习更轻松，效果更好

## 🎨 产品逻辑

### 学习阶段流程图

```
开始
  ↓
创建学习计划
  ↓
每天定时任务生成
  ↓
┌─────────────────────────────────┐
│ 选择新词：完全未标记的词        │
│ 选择复习词：标记"认识"的词      │
│ 混合分配到今日任务              │
└─────────────────────────────────┘
  ↓
用户学习（标记任何状态）
  ↓
【检测：所有词都标记过？】
  ├─ 否 → 继续学习阶段
  └─ 是 → 进入复习阶段 ✓
```

### 复习阶段流程图

```
进入复习阶段
  ↓
每天定时任务生成
  ↓
┌─────────────────────────────────┐
│ 选择复习词：根据艾宾浩斯曲线    │
│ - 7天后需复习的词               │
│ - 15天后需复习的词              │
│ - 30天后需复习的词              │
└─────────────────────────────────┘
  ↓
用户学习（标记任何状态）
  ↓
【更新复习间隔】
├─ 标记"认识" → 间隔翻倍（7→15→30）
├─ 标记"模糊" → 间隔重置为1天
└─ 标记"不认识" → 间隔重置为1天
  ↓
继续复习（永不结束）
```

### 核心规则

| 场景 | 学习阶段 | 复习阶段 |
|------|----------|----------|
| **新词来源** | 完全未标记的词 | 无（0个新词） |
| **复习词来源** | 标记"认识"的词（1天后复习） | 根据艾宾浩斯曲线 |
| **标记"认识"后** | 明天复习 | 间隔翻倍 |
| **标记"模糊"后** | 不再出现 | 明天继续复习 |
| **标记"不认识"后** | 不再出现 | 明天继续复习 |
| **今日完成条件** | 所有词都标记过 | 所有词都标记过 |
| **阶段完成条件** | 所有词都标记过 | 永不结束 |

## ⚙️ 后端逻辑

### 1. 新词生成逻辑（学习阶段）

**旧逻辑**：
```sql
-- 选择 status != 'known' 的词
SELECT * FROM words
WHERE book_id = ?
  AND (status IS NULL OR status != 'known')
LIMIT 20
```

**新逻辑**：
```sql
-- 选择完全未标记的词（word_progress 表中没有记录）
SELECT * FROM words w
WHERE w.book_id = ?
  AND NOT EXISTS (
    SELECT 1 FROM word_progress wp
    WHERE wp.word_id = w.id
      AND wp.user_id = ?
  )
LIMIT 20
```

### 2. 完成检测逻辑

**检测时机**：每天生成定时任务时

**检测逻辑**：
```sql
-- 检查是否所有单词都已标记
SELECT
  COUNT(*) as total_words,
  COUNT(DISTINCT wp.word_id) as marked_words
FROM words w
LEFT JOIN word_progress wp ON w.id = wp.word_id AND wp.user_id = ?
WHERE w.book_id = ?

-- 如果 total_words = marked_words，则学习阶段完成
```

**完成操作**：
```sql
-- 更新学习计划状态
UPDATE learning_plans
SET status = 'review',
    completed_at = NOW()
WHERE book_id = ?
  AND user_id = ?
```

### 3. 复习词生成逻辑（复习阶段）

**数据结构**：`review_schedule` 表

| 字段 | 说明 |
|------|------|
| word_id | 单词ID |
| user_id | 用户ID |
| next_review_date | 下次复习日期 |
| review_interval | 当前间隔（天） |
| review_count | 复习次数 |

**复习词查询**：
```sql
-- 查询今天需要复习的词
SELECT w.*, rs.review_interval
FROM review_schedule rs
JOIN words w ON rs.word_id = w.id
WHERE rs.user_id = ?
  AND rs.next_review_date <= CURRENT_DATE
ORDER BY rs.next_review_date ASC
LIMIT 50
```

### 4. 复习间隔更新逻辑

**用户标记"认识"**：
```sql
-- 间隔翻倍（7 → 15 → 30 → 60）
UPDATE review_schedule
SET next_review_date = CURRENT_DATE + (review_interval * 2),
    review_interval = review_interval * 2,
    review_count = review_count + 1
WHERE word_id = ?
  AND user_id = ?
```

**用户标记"模糊"或"不认识"**：
```sql
-- 间隔重置为1天
UPDATE review_schedule
SET next_review_date = CURRENT_DATE + INTERVAL '1 day',
    review_interval = 1,
    review_count = 0
WHERE word_id = ?
  AND user_id = ?
```

   - 用户知道当前在哪个阶段
   - 用户知道"完成"的定义

2. **操作正确性**

   - 用户理解标记"模糊"/"不认识"的价值

   - 用户感受到学习计划的明确终点
   - 用户对复习阶段的价值认可

### 艾宾浩斯遗忘曲线

| 复习次数 | 复习间隔 | 记忆保持率 |
|----------|----------|------------|
| 第1次 | 1天后 | 75% |
| 第2次 | 7天后 | 85% |
| 第3次 | 15天后 | 90% |
| 第4次 | 30天后 | 95% |

**系统实现**：
- 标记"认识" → 间隔翻倍（1 → 7 → 15 → 30）
- 标记"模糊"/"不认识" → 间隔重置为1天

### 常见问题

**Q1: 为什么标记"模糊"/"不认识"也算完成？**

A: 因为"完成"不等于"掌握"。"完成"表示你已经学习过这个词，对它有了初步印象。标记"模糊"或"不认识"表明你还需要继续巩固，系统会安排你明天继续学习。

**Q2: 复习阶段会结束吗？**

A: 复习阶段永不结束。根据艾宾浩斯遗忘曲线，记忆需要长期巩固。系统会根据你的标记情况智能安排复习间隔。

**Q3: 我应该诚实标记还是都标记"认识"？**

A: 强烈建议诚实标记。如果你标记"认识"但实际上不会，这个词就不会再出现，你永远不会真正掌握。诚实标记能让系统帮你安排最合适的学习节奏。

**Q4: 复习阶段为什么没有新词？**

A: 复习阶段的目的是巩固已学过的单词。如果你还想学习新词，可以创建一个新的学习计划。
