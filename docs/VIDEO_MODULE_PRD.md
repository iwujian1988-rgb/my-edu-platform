## 一、模块定位

### 1.1 产品定位

独立售卖的视频学习模块，与现有词书系统完全独立：
- **独立售卖** - 套餐与视频内容灵活关联（A套餐→视频1-10，B套餐→视频11-20）
- **复用认证逻辑** - 用现有的用户认证和邀请码系统
- **独立导航入口** - 不复用旧首页，有独立的导航体系
- **不与词书系统联动**
- **完整功能**（视频+字幕+卡片+录音+复习）
- **多语言支持** - 每个视频关联一个语言（英语/法语/德语等）

### 1.2 目标用户

- 想要通过视频学习地道口语表达的用户
- 已有词汇基础，想提升口语和听力的用户
- 喜欢通过场景化内容学习的用户

### 1.3 核心价值

1. **真实场景** - YouTube 精选视频，地道口语
2. **即时学习** - 字幕点击即学，无需跳转
3. **系统复习** - 艾宾浩斯遗忘曲线，科学复习
4. **跟读练习** - 录音对比，纠正发音

### 1.4 套餐-视频关联模型（核心售卖逻辑）

### 1.5 视频语言关联规则

- **一个视频只关联一个语言**（英语/法语/德语/西班牙语/日语/意大利语/俄语）
- **语言在管理后台上传视频时由管理员手动指定**
- 用户通过浏览不同语言的视频来学习不同语言
- 套餐可按语言分类（如"英语包"、"法语包"），也可跨语言（如"全语言通票"）

### 7.3 用户购买流程

```
1. 用户购买邀请码
   └─▶ 邀请码关联某个 invitation_package
       └─▶ invitation_package 关联某个 video_package

2. 用户激活邀请码
   └─▶ 系统在 user_video_packages 表创建记录
       └─▶ 用户获得对应 video_package 的视频访问权限

3. 用户访问视频
   └─▶ 系统检查 user_video_packages → package_video_relations → videos
       └─▶ 有记录则允许访问，否则提示购买
```

### 7.4 权限检查逻辑

```typescript
// 检查用户是否有某个视频的访问权限
async function hasVideoAccess(userId: string, videoId: string): Promise<boolean> {
  // 查询：用户已购套餐 → 套餐包含的视频
  const hasAccess = await supabase
    .from('user_video_packages')
    .select('id')
    .eq('user_id', userId)
    .eq('is_active', true)
    .in('package_id', {
      // 子查询：包含该视频的套餐
      select: 'package_id from package_video_relations where video_id = ?'
    })
    .single()

  return !!hasAccess
}
```

### 7.5 视频语言规则

- **一个视频只关联一个语言**
- **语言在管理后台上传视频时由管理员手动指定**
- 套餐可按语言分类，也可跨语言
- 用户通过浏览不同语言的视频来学习不同语言
